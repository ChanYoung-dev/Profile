# 1번페이지
개발자들이 AI 도구를 사용할 때 사용하지 않을때보다 19% 더 오래걸린다. AI가 오히려 개발 속도를 늦춥니다


# 2번 페이지
이유 1번
- 1. 컨벤션이 일관되지 않으면 AI 결과도 일관되지 않다
  - 코드를 이해하는데 오랜시간이 걸린다.
  - ex) 우리 프로젝트는 mybatis형식이지만 jpa로 작성을 함

# 3번 페이지
이유 2번
- 2. 컨텍스트가 없거나 너무 길면 AI는 “그럴듯한 일반론”으로 답한다
  - “교환완료/반품완료 이후에는 주문상태를 변경할 수 없다”
  - 이 정책이 문서화되어 있지 않거나, 문서가 있어도 AI가 못 찾으면 AI는 일반적인 주문 시스템 기준으로 판단합니다.

# 4번 페이지
이유 3번
- 3. 도구 활용 편차가 크다
  - AI를 그냥 채팅창처럼 쓰는 사람과, Claude Code처럼 코드베이스 탐색·수정·테스트·문서화를 연결해서 쓰는 사람의 생산성은 완전히 다르다
  - "이 기능 추가해줘" 라고 개발하는 사람 vs
```
1. 관련 정책 문서 먼저 찾아라
2. 기존 컨벤션을 확인해라
3. 수정 후보 파일을 제시해라
4. 변경 전 영향 범위를 정리해라
5. 최소 수정으로 구현해라
6. 테스트 케이스를 추가해라
7. 사이드이펙트를 리뷰해라
8. Jira용 사업부 설명을 작성해라
```
요렇게 개발하는 사람

# 5번페이지
