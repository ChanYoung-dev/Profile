자기소개
저는 복잡한 도메인을 객체지향적으로 정리하고, 운영 환경에서 발생하는 문제를 구조적으로 해결하는 서버 개발자입니다.
커머스 환경에서 주문·결제·배송과 같이 정합성과 신뢰성이 곧 서비스 품질로 직결되는 영역을 담당하며, 단순 기능 구현보다 장기적으로 안전하고 확장 가능한 구조를 만드는 데 집중해 왔습니다.

직무 적합성 및 강점
1. 결제 수단 객체지향 리팩토링 경험

초기 결제 로직은 카드, 포인트, 간편결제 등 결제 수단에 따라 if-else로 분기되는 구조였고, 복합 결제나 정책 변경이 발생할 때마다 기존 로직 수정으로 인한 사이드 이펙트가 반복되었습니다.

이 문제를 해결하기 위해 결제 방식을 조건이 아닌 객체의 책임으로 분리하고, 전략 패턴과 인터페이스 기반 설계를 적용하여 결제 수단을 독립적인 객체로 재구성했습니다. 결제 선택 로직 또한 팩토리로 캡슐화하여, 새로운 결제 수단이 추가되더라도 기존 주문·결제 로직을 수정하지 않고 확장할 수 있는 구조를 만들었습니다.

그 결과 정책 변경과 신규 결제 수단 추가 시 영향 범위를 최소화할 수 있었고, 복잡한 결제 도메인을 보다 안정적으로 운영할 수 있게 되었습니다.

2. XSS 보안 프로그래밍 경험

MSA 환경에서 서비스별로 XSS 대응 방식이 제각각 적용되어 있어, 이중 이스케이프, JSON 파싱 오류, 화면별 상이한 출력 문제 등이 반복적으로 발생했습니다.

이를 해결하기 위해 정보보안팀의 정책 기준으로 XSS 처리 원칙을 정립했습니다. 이후 애노테이션 기반의 공통 처리 방식을 도입해 전사 서비스에 일관되게 적용했습니다.

그 결과 보안 취약점 재발을 방지함과 동시에, ISMS 점검 과정에서 XSS 관련 지적 건수를 크게 줄이는 성과를 냈습니다.

3. MQ 기반 비동기 처리로 안정성 확보

주문 완료 이후 수행되는 e쿠폰 발급, 이메일, 현금영수증과 같은 후행 작업을 초기에는 동기 방식으로 처리하면서 외부 장애가 주문 전체 흐름에 전파되는 문제가 있었습니다.

이를 해결하기 위해 RabbitMQ를 도입해 주문의 핵심 흐름과 후행 작업을 분리했고, 재시도와 DLQ를 통해 외부 장애를 운영적으로 흡수할 수 있도록 설계했습니다.

이 구조를 통해 주문 API 응답 지연 문제를 해소하고, 외부 시스템 장애 상황에서도 주문 도메인의 안정성을 유지할 수 있었습니다.

4. 멀티프로세스 기반 대규모 처리 경험

개인 프로젝트로 코인 자동매매 및 백테스트 시스템을 개발하며,
수백만 건 이상의 데이터를 단일 프로세스로 처리하는 데 한계를 경험했습니다.

이 과정에서 멀티프로세스를 도입해 병렬 처리를 구현했고, 메모리 격리와 장애 전파 차단을 고려해 프로세스 단위로 작업을 분산했습니다.
또한 OOM 문제를 겪으며 “한 번에 처리하지 않고, 나누어 처리하고, 즉시 비운다”는 원칙으로 구조를 개선해 시스템 안정성과 처리 성능을 동시에 확보했습니다.
